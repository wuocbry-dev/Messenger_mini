Implement file/image attachment storage using Cloudflare R2.

Read docs/STORAGE.md first.

Architecture:

ObjectStorageService
        ↓
R2StorageService

R2 stores binary objects.

MySQL stored_files stores metadata only.

Never store:
- blob contents in MySQL
- R2 secret in frontend
- temporary presigned URLs in database

Implement initial APIs such as:

POST /api/v1/files
GET  /api/v1/files/{fileId}/download

Choose whether the first implementation uploads through Spring Boot or
uses presigned URLs.

For the university project, prefer correctness and security over premature
optimization.

Validate:
- file size
- allowed MIME/file types according to documented policy
- authorization
- object key generated by server
- original filename not trusted as storage key

Persist:

uploaderId
objectKey
originalName
mimeType
sizeBytes
checksum if implemented
etag if available
createdAt

Integrate message_attachments so a FILE/IMAGE message can reference the
stored file.

Do not expose R2 secret credentials.

Handle cleanup if R2 upload succeeds but DB transaction fails where
practical.

Add tests with storage abstraction/mock; tests must not require real R2.

Run clean verify.

Stop before Agora.
