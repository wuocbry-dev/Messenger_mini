# Task

## Objective

Prepare a safe local runtime configuration workflow for the backend so Spring Boot can be started consistently without committing secrets.

## Context

Backend runtime verification now has a working Maven Wrapper. The backend can be run with local environment variables from ignored `backend/.env`.

The project must keep secrets out of source control while still making local startup easy for developers.

## Functional Requirements

- Document how to run the backend locally with `backend/.env`.
- Ensure committed examples remain safe and do not contain real secrets.
- Ensure `backend/.env` remains ignored by Git.
- Avoid relying on global Maven; use Maven Wrapper commands.
- Keep Flyway enabled.
- Keep Hibernate `ddl-auto=validate`.
- Do not enable permanent `baseline-on-migrate=true`.
- Do not require real R2 or Agora credentials for basic backend startup.

## API Contract

No REST or WebSocket API changes.

## Business Rules

Do not implement authentication, chat, file storage, voice call, or other business features.

## Database Impact

Allowed:

- Read schema metadata.
- Read row counts.
- Read `flyway_schema_history`.

Forbidden:

- Dropping the database.
- Dropping or recreating tables.
- Deleting or inserting application data.
- Running `V1__initial_schema.sql` against the already-baselined existing database.

## Realtime Impact

None.

## Security Requirements

- Do not commit `backend/.env`.
- Do not print secrets in final output.
- Do not commit DB password, JWT secret, R2 secret, or Agora App Certificate.
- Keep `.env.example` files safe.

## Error Cases

- If local startup requires a real secret for an unused integration, adjust configuration boundaries so placeholder values are sufficient.
- If `backend/.env` is not ignored, stop and fix `.gitignore`.
- If Flyway attempts to run `V1` against the existing database, stop and investigate.
- If Hibernate validation fails, report the exact schema mismatch and fix mappings only when consistent with the approved schema.

## Tests

Run from `backend/`:

```bash
.\mvnw.cmd -v
.\mvnw.cmd clean verify
```

Start backend with local env loaded:

```powershell
Get-Content .env | ForEach-Object {
  if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
    [Environment]::SetEnvironmentVariable($matches[1].Trim(), $matches[2].Trim(), 'Process')
  }
}
.\mvnw.cmd spring-boot:run
```

Verify:

- Backend starts successfully.
- Flyway reports schema is up to date.
- Hibernate validation succeeds.
- `/v3/api-docs` returns title `Messenger Mini API` and version `v1`.
- Swagger UI is reachable.
- Application table row counts are unchanged.

## Acceptance Criteria

- Local backend startup procedure is documented.
- Maven Wrapper is used for all Maven commands.
- Runtime configuration does not expose committed secrets.
- Existing database data is preserved.
- Remaining local setup blockers are reported exactly.

## Out of Scope

- Authentication implementation.
- JWT login/register endpoints.
- Business feature implementation.
- New schema migrations beyond the approved baseline.
- Production deployment configuration.
