# Messenger Mini Agent Contract

## 1. Project Identity
Messenger Mini is a university project for a web-based real-time messenger with authentication, profiles, direct conversations, chat, presence, typing indicators, receipts, attachments, 1-to-1 voice calls, and call history.

## 2. Fixed Stack
- Backend: Java, Spring Boot, Maven, Spring Web, Spring Data JPA/Hibernate, Spring Security, JWT, WebSocket/STOMP, Bean Validation, Flyway, springdoc-openapi, MySQL 8.x.
- Frontend: Vite, React, TypeScript.
- Storage: Cloudflare R2 for file/image binaries; MySQL stores metadata only.
- Voice: Agora RTC for media transport; Spring Boot owns authorization, call state, channel naming, token generation, and call history.

## 3. Architecture Rules
- Use client-server architecture.
- Use a modular monolith, not microservices.
- Organize by business feature first, then by layer inside each feature.
- Do not add Kafka, Kubernetes, Redis, MongoDB, or other major technologies unless the user explicitly approves.

## 4. Feature-Based Rules
- Backend packages belong under `com.team503.messenger`.
- Backend features include `auth`, `user`, `conversation`, `message`, `presence`, `file`, `call`, and `notification`.
- Frontend feature code belongs under `frontend/src/features`.
- Shared frontend utilities belong under `frontend/src/shared`; app wiring belongs under `frontend/src/app`.
- Do not create project-wide `controller/`, `service/`, `repository/`, or `entity/` packages.

## 5. Backend Dependency Direction
Controllers and WebSocket handlers call services. Services coordinate business rules and repositories. Repositories own persistence access only. Repositories must not contain business logic.

## 6. DTO / Entity Rules
- Do not expose JPA entities directly from REST controllers.
- Use request DTOs for incoming payloads and response DTOs for public output.
- Never return `passwordHash` or secret material in API responses.

## 7. Database Rules
- MySQL 8.x is the primary relational database.
- Files and images are never stored as MySQL blobs.
- `stored_files` stores metadata and object keys only.
- Presence is primarily realtime/in-memory/WebSocket state; `users.last_seen_at` persists last seen information.

## 8. Flyway Rules
- Flyway owns schema evolution.
- Hibernate `ddl-auto` must not be `update`; prefer `validate`.
- Do not manually modify a production schema instead of creating a migration.
- Migration files live in `backend/src/main/resources/db/migration/`.

## 9. WebSocket Rules
- Use WebSocket + STOMP for realtime chat events, typing, delivered/read receipts, presence, and call signaling where appropriate.
- REST is primarily for resource and query operations.

## 10. Cloudflare R2 Rules
- Backend owns R2 credentials and object-key generation.
- Do not expose `R2_SECRET_ACCESS_KEY` to the frontend.
- Do not persist temporary presigned URLs; persist object keys.

## 11. Agora Security Rules
- Agora App Certificate is backend-only.
- Temporary Agora RTC tokens are generated by the backend and must not be persisted in `calls`.
- Agora carries voice media; Spring Boot does not proxy media streams.

## 12. Security Rules
- Authentication uses Spring Security + JWT.
- Secrets must come from environment/config and must never be committed.
- Vite `VITE_*` variables may contain public values only.

## 13. Testing Expectations
- Add focused tests for new business rules, persistence behavior, security-sensitive code, and realtime/call state transitions.
- Do not claim tests passed unless they were actually run.

## 14. Naming Conventions
- Java packages: lowercase feature names.
- Java classes: PascalCase.
- DTOs: suffix request DTOs with `Request` and response DTOs with `Response`.
- Flyway migrations: `V<version>__<description>.sql`.
- REST paths: `/api/v1/...`.

## 15. Documentation Updates
- Update `docs/` when architectural decisions, database shape, realtime contracts, storage behavior, or voice-call design changes.
- Update `docs/DECISIONS.md` only for accepted architecture decisions.
- Do not silently erase historical design decisions after completing a task.

## 16. Task Instructions
- Task specification files are no longer kept in the repository.
- Current direct user instructions are the source of truth for the task at hand.

## 17. Forbidden Changes Without Approval
Do not switch away from Spring Boot, Vite React TypeScript, MySQL, Flyway, WebSocket/STOMP, Cloudflare R2, Agora RTC, feature-based modular monolith architecture, or Spring Security + JWT unless the user explicitly approves the change.
